# 07 — Database Schema

## Storage & access

- **Physical store:** Microsoft Access `varManager.mdb`, reached via **ACE OLEDB 12.0**.
  - Connection string (App.config, the only wired-up path): `Provider=Microsoft.ACE.OLEDB.12.0;Data Source=|DataDirectory|\varManager.mdb`, `providerName="System.Data.OleDb"`.
- **Access layer:** a strongly-typed `varManagerDataSet` (generated by `MSDataSetGenerator` from `varManagerDataSet.xsd`) + `TableAdapter`s. The full table is `Fill`ed into memory on startup; almost all *reads* are **LINQ-to-DataSet** over the in-memory tables; *writes* go back per-row through TableAdapters. No hand-written `OleDbCommand`/SQL anywhere except what's baked into the XSD.
- **Staged, unfinished SQLite migration:** App.config also registers EntityFramework 6 (`System.Data.SqlClient` + `System.Data.SQLite.EF6`) and a `System.Data.SQLite` DbProviderFactory — but **no SQLite connection string**, and the csproj still copies `varManager.mdb` to output. So at this snapshot it **runs on Access**; SQLite is intended but not live. ✎ Rebuild target: SQLite + EF Core; drop SqlClient entirely.

## The 9 DataTables — base tables, views, and phantoms

| DataTable | Real nature |
|---|---|
| `vars` | Base table |
| `scenes` | Base table |
| `dependencies` | Base table |
| `savedepens` | Base table |
| `installStatus` | Base table (regenerated each sync) |
| `varsView` | **Access VIEW** over `vars` ⋈ `installStatus` (read-only) |
| `installedScenes` | **Access VIEW** over `scenes`⋈`vars`⋈`installStatus`, installed only (read-only; unused by the inspected forms) |
| `scenesView` | **In-memory only** — built in C# (`FormScenes`), never persisted |
| `HideFav` | **In-memory only, effectively dead** — hide/fav state lives on disk as sidecar files |

⚠ **There are ZERO foreign keys / relationships** in the DataSet or Access. Every cross-table link is a bare `varName` string enforced only in application code. Deleting a var leaves dangling `scenes`/`dependencies`/`installStatus` rows unless code cleans them.

## Exact columns (from the XSD)

Type mapping: `xs:int` = Access Long; `xs:string maxLength 255` = Text(255); `xs:boolean` = Yes/No; `xs:dateTime` = Date/Time; `xs:double` = Double. Autoincrement PKs use the ADO.NET negative client temp-key pattern (`seed=-1, step=-1`); real identity is Access AutoNumber.

### `vars` — PK `varName`
`varName`(str255, PK), `varPath`(str255), `creatorName`(str255), `packageName`(str255), `version`(int), `metaDate`(date), `varDate`(date), `filesize`(double, def 0), `scenes/looks/clothing/hairstyle/plugins/assets/morphs/pose/skin`(int content counts, def 0), `addedDate`(date), **`installedDate`(str255 — anomaly: text, while sibling dates are real `dateTime`)**.

> `varName` = `creatorName.packageName.version` serialized. The table stores **both** the composite string (PK) **and** its three decomposed parts — redundant/denormalized; code uses both `FindByvarName` and `GroupBy(creatorName,packageName).Max(version)`.

### `scenes` — PK `ID`
`ID`(autonum, PK), `varName`(str255, logical FK→vars), `atomType`(str255), `isPreset`(bool, def false), `scenePath`(str255, ZIP entry path), `previewPic`(str255, cached JPG filename).

### `dependencies` — PK `ID`
`ID`(autonum, PK), `varName`(str255, logical FK→vars), `dependency`(str255, referenced varName). Self-referential many-to-many on vars.

### `savedepens` — PK `ID`
`ID`(autonum, PK), `savepath`(str255), `modidate`(date), `dependency`(str255, referenced varName). Links a loose save/scene file → a required var.

### `installStatus` — PK `varName`
`varName`(str255, PK, logical FK→vars), `Installed`(bool, def false), `Disabled`(bool, def false). **Regenerated each sync** via `DeleteAll()` + re-insert.

### `varsView` (Access VIEW) — all `vars` columns + `Installed`, `Disabled`, plus computed **`fsize`**(double, `msdata:ReadOnly`, a human-friendly MB size). Inferred SQL: `vars LEFT JOIN installStatus ON varName`. The grid's data source.

### `installedScenes` (Access VIEW) — `ID, atomType, varName, scenePath, previewPic, metaDate, varDate, Installed`. `scenes`⋈`vars`⋈`installStatus`, installed only.

### `scenesView` (in-memory) — `location`(str, synthetic: "installed"/"not Installed"/"missingLink"/"Save"), `varName, atomType, isPreset, scenePath, previewPic, Installed, creatorName, packageName, varPath, filesize, metaDate, varDate, hidefav`(int). A denormalized display projection built by `FormScenes` from `scenes`+`vars`+install state+filesystem hide/fav.

### `HideFav` (in-memory, dead) — `varName, scenePath, hidefav`. All usages commented out.

## Notable generated queries (baked into the XSD)
Access dialect: backtick quoting, `?` positional params.
- `installStatus.DeleteAll` → `DELETE * FROM \`installStatus\``
- `savedepens.FillByDepens` → `SELECT ... FROM savedepens WHERE (dependency = ?)`
- `scenes.GetDataByVarName` → `... WHERE (varName = ?)`
- `scenes.GetByLoadable` → `... WHERE (atomType = 'scenes') OR (isPreset = true)`

## ⚠ Hide/Favorite state lives on disk, not in the DB
`FormScenes.GetHideFav`/`SetHideFav` read/write **marker files** under `{vampath}\AddonPackagesFilePrefs\`: `{scene}.hide` → hidden, `{scene}.fav` (and `*.vap.fav`) → favorite, else normal. The `HideFav` table is a declared-but-unused placeholder. A rebuild should promote this to a real table.

## Proposed modern schema (SQLite / EF Core)

Goals: same data + real FKs + indexes, normalize the `varName` redundancy, fix the `installedDate` text-date bug, fold `installStatus`/`HideFav` into first-class tables, and make the views real SQL views.

```sql
CREATE TABLE vars (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    var_name       TEXT    NOT NULL UNIQUE,          -- "creator.package.version"
    creator_name   TEXT    NOT NULL,
    package_name   TEXT    NOT NULL,
    version        INTEGER NOT NULL,
    var_path       TEXT,
    meta_date      TEXT, var_date TEXT, added_date TEXT, installed_date TEXT,  -- ISO-8601
    filesize       REAL    NOT NULL DEFAULT 0,
    scenes_count   INTEGER NOT NULL DEFAULT 0,        -- renamed: 'scenes' collided with table
    looks INTEGER NOT NULL DEFAULT 0, clothing INTEGER NOT NULL DEFAULT 0,
    hairstyle INTEGER NOT NULL DEFAULT 0, plugins INTEGER NOT NULL DEFAULT 0,
    assets INTEGER NOT NULL DEFAULT 0, morphs INTEGER NOT NULL DEFAULT 0,
    pose INTEGER NOT NULL DEFAULT 0, skin INTEGER NOT NULL DEFAULT 0,
    UNIQUE (creator_name, package_name, version)
);
CREATE INDEX ix_vars_creator_package ON vars (creator_name, package_name);

CREATE TABLE install_status (
    var_id    INTEGER PRIMARY KEY REFERENCES vars(id) ON DELETE CASCADE,
    installed INTEGER NOT NULL DEFAULT 0,
    disabled  INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE scenes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    var_id INTEGER REFERENCES vars(id) ON DELETE CASCADE,
    atom_type TEXT, is_preset INTEGER NOT NULL DEFAULT 0,
    scene_path TEXT, preview_pic TEXT
);
CREATE INDEX ix_scenes_var ON scenes (var_id);
CREATE INDEX ix_scenes_atomtype ON scenes (atom_type);

CREATE TABLE dependencies (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    var_id INTEGER REFERENCES vars(id) ON DELETE CASCADE,
    dependency TEXT NOT NULL                          -- referenced varName (may be unknown)
);
CREATE INDEX ix_dependencies_var ON dependencies (var_id);
CREATE INDEX ix_dependencies_dep ON dependencies (dependency);

CREATE TABLE save_depends (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    save_path TEXT, modi_date TEXT, dependency TEXT NOT NULL
);
CREATE INDEX ix_savedepends_dep ON save_depends (dependency);

CREATE TABLE scene_flags (                            -- promotes .hide/.fav files into the DB
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    var_name TEXT NOT NULL DEFAULT '', scene_path TEXT NOT NULL,
    hidefav INTEGER NOT NULL DEFAULT 0,               -- -1 hide, 0 normal, 1 fav
    UNIQUE (var_name, scene_path)
);

CREATE VIEW vars_view AS
  SELECT v.*, COALESCE(s.installed,0) AS installed, COALESCE(s.disabled,0) AS disabled,
         ROUND(v.filesize/1048576.0, 2) AS fsize
  FROM vars v LEFT JOIN install_status s ON s.var_id = v.id;
-- installed_scenes and scenes_view analogous (scenes ⋈ vars ⋈ install_status [⋈ scene_flags]).
```

### Improvements over the original
1. **Real FKs + `ON DELETE CASCADE`** — the original had none; removes orphan-row bug classes.
2. **Normalize the composite key** — surrogate `id` + `UNIQUE(creator,package,version)`; children reference `var_id` (int), not repeated 255-char strings. Keep `var_name` as a unique alias.
3. **Fix `installedDate`** — real date, not `TEXT(255)`.
4. **Indexes** — none existed; add them on the hot paths (creator+package, `scenes.var_id/atom_type`, `dependencies.var_id/dependency`, `save_depends.dependency`).
5. **`install_status` upsert** instead of the race-prone delete-all snapshot.
6. **Promote hide/fav** into `scene_flags` (back-fill from the on-disk `.hide`/`.fav` markers during migration).
7. **`fsize`/`location`** become computed/view expressions, not stored mystery columns.
8. Booleans → SQLite `INTEGER 0/1`.

### Migration Access → SQLite
`vars/scenes/dependencies/savedepens/installStatus` copy row-for-row. `varsView`/`installedScenes` are recreated as views. `scenesView` carries no persistent data (rebuilt at runtime). `HideFav` back-fills into `scene_flags` from the filesystem markers.
