# New App — Data Architecture: Adversarial Review & Resolutions

Consolidated findings from four adversarial reviewers (performance/scale · correctness/integrity · data-loss/safety · VaM-domain/edge-cases) attacking [03-Data-Architecture.md](./03-Data-Architecture.md). Deduplicated, grouped by **root cause**, severity-ranked, each with a resolution. This drives the **v2** of the data architecture.

**Verdict:** the Package-vs-VarFile split and "don't load everything" instincts are sound. But the draft (a) **derives identity from a parsed `int Version`** instead of the real filename, (b) **hangs physical-per-file facts on the logical Package**, (c) **has no durability discipline** behind its safety promises, (d) **defers all aggregates/recompute to query time**, and (e) **forgets several load-bearing VaM concepts** (user saves, profiles, alias links). None are fatal to SQLite+EF Core; all are fixable now, before schema lock.

---

## The 8 structural root causes (fix these → most findings close)

### R1. Identity must be the verbatim filename, not a reconstruction  🔴 CRITICAL
`Package.Version:int` + a *reconstructed* `VarName` loses the real on-disk name: `Creator.Pkg.007` → `.7` (breaks the activation symlink target and every by-name dependency match), 11-digit versions **overflow Int32**, and populating `Creator`/`PackageName` from `meta.json` (which often disagrees with the filename) mis-resolves every dependency edge. *(VaM-1, VaM-2)*
**Resolution:** store the **verbatim base filename** as the canonical identity string (persisted). Derive `Creator`/`PackageName`/`VersionToken` as facets **from the filename**, never from `meta.json`; keep version as the original **string** + a numeric sort key (or `long`). Add optional `MetaCreatorName`/`MetaPackageName` and flag when they diverge. Apply **case-insensitive matching** (`NOCASE`/normalized fold key) on every identity/reference column (`VarName`, `DependsOnRef`, `PackageRef`, `MissingRef`, entry-path matches) — NTFS and VaM are case-insensitive; binary collation double-counts packages and misses dependency joins. Preserve original casing for display. (Note: SQLite `NOCASE` is ASCII-only → compute an app-side fold key for non-ASCII creator names.)

### R2. Physical-per-file facts belong on VarFile, not Package  🔴 CRITICAL
`ContentItem`, the extracted **dependency set**, and **content counts** are keyed on `PackageId` — but copies of the same `Creator.Package.Version` can differ (corrupt vs. encoding-fixed → different content, different `meta.json`, **different dependency list**). One Package row then shows whichever copy was "canonical", nondeterministically; if the empty-deps copy wins, the forward closure silently omits real dependencies and the game fails **with no missing-deps warning**. *(Corr-H1, VaM-6, Corr-root-1)*
**Resolution:** key `ContentItem` and the **extracted dependency set on `VarFileId`**. Derive Package-level counts/deps from a **deterministically elected canonical VarFile** (prefer `IntegrityStatus=Ok` + `EncodingHealth=Ok`, then newest `MetaDate`, tie-break lowest `Id`). Surface a hard **content-conflict** state when online copies of one Package.Version disagree, instead of silently picking one.

### R3. Break the circular canonical FK  🔴 CRITICAL
`Package.CanonicalVarFileId → VarFile` and `VarFile.PackageId → Package` form a cycle. Cascade on VarFile delete can **annihilate the Package** (and its favorites/tags/usage/presets — violating the design's core promise); no-cascade leaves it dangling with no re-election. *(Corr-C3)*
**Resolution:** `CanonicalVarFileId` nullable, `ON DELETE SET NULL`, with a deterministic **re-election** on canonical loss (rule from R2). VarFile deletion must **never** cascade into Package.

### R4. One deletion predicate gates every destructive path  🔴 CRITICAL
Multiple independent ways to delete the only copy of irreplaceable content: dedup groups by `ContentSignature` **across different Package identities** and deletes a uniquely-named var that dependents reference by name (*Corr-C1*); `InstanceCount`/single-copy counts **offline** copies, so the user deletes the only *online* copy trusting an unverifiable offline twin (*Corr-C2, Loss-C4*); reclaim wizard offers **single-copy "never-loaded orphans"** for one-confirm delete — never-loaded ≠ unwanted (*Loss-C7*); deletion proceeds on **signature/presence alone** (CRC-32 is 32-bit, a truncated var can have a valid central directory) (*Loss-C5*).
**Resolution:** a single hard precondition on **all** delete paths (dedup, reclaim, version-prune, intake): *delete a VarFile only if another copy of the **same Package identity** is currently **online** and its **full `ContentHash` is computed and equals** the candidate's.* Cross-identity `ContentSignature` matches are **report-only**, never delete candidates. Split `OnlineInstanceCount` vs `TotalInstanceCount`; the single-copy/irreplaceable flag is a **hard gate**, not a badge. Block dedup/reclaim on any group with offline members or unverifiable copies.

### R5. Durability discipline for every physical operation  🔴 CRITICAL
Safety is stated as aspiration with no mechanism. Verify re-reads from the **OS page cache**, not the platter → a "verified" move deletes the source before the target is actually on disk (*Loss-C1*). No fsync/ordering barrier between the DB state transition and the irreversible FS op; a tempting `synchronous=NORMAL/OFF` loses the transition record (*Loss-C2*). Interrupted copy leaves a **partial file at the real path** that reconcile indexes as a real var (*Loss-H3*). Two jobs race the same file / stale `FreeBytes` overfills a drive (*Loss-H1, H2*).
**Resolution:** codify the rules: **temp-write → `FlushFileBuffers` → cache-bypassed verify (`FILE_FLAG_NO_BUFFERING`) → atomic rename → persist completion**; `synchronous=FULL` on any transaction gating a destructive FS op; order **persist-state → flush → FS-op → persist-completion** with idempotent resume; unique partial index `MigrationJob(VarFileId) WHERE State NOT IN (Done,Failed,Cancelled)` (one live job per file); an in-flight **free-space reservation ledger**; **never migrate *to* a removable/network tier**, and never delete the last online copy for a move onto a single target until a post-write cache-bypassed re-read confirms it.

### R6. The catalog DB and trash are safety infrastructure, not conveniences  🔴 CRITICAL
The single SQLite file holds all logical state **plus** trash manifest, migration state, and single-copy determinations — and backup is only `[should]` (*Loss-C8*). Trash has no defined location/quota/capacity behavior; trashing a 200 GB var onto a full/removable/system drive silently fails or vanishes (*Loss-M1, M5*).
**Resolution:** promote **automatic versioned DB backups to CORE** (checkpoint + copy on a schedule *and before every destructive batch*); `PRAGMA integrity_check` on startup; **pin the DB to stable local storage**, refuse to run if it's on a repo/removable volume. Define **trash** as a same-volume move where possible (instant, no copy), with quota + capacity-aware behavior, **never a silent hard-delete fallback**, never the only copy of anything, and a **per-item restore manifest stored inside the trash** (survives DB loss).

### R7. A single recompute pipeline with defined transaction boundaries  🟠 HIGH
Resolution, `IsMissing`, centrality, the read model, and `UsageStat` all "recompute when things change" with no owner, ordering, or atomicity → pervasive silent drift. `latest`/closest-newer resolution is **non-monotonic**: indexing `B.Cloth.3` silently flips a preset's resolved `5→3` (*Corr-H2*). Aliases live in a **separate** resolution path from `Dependency.IsMissing`, so the grid shows "missing" (red) while the loader silently satisfies via alias (*Corr-H3*). Windowed `UseCount30d/90d` are **wrong the day after they're written** because the window slides with time, not writes (*Corr-H4*).
**Resolution:** nominate a **single-writer recompute pipeline**; define exactly which base-table writes dirty which derived rows and refresh them **in the same transaction** (or a durable dirty-queue). Fold **alias application into the one resolution pass** that writes `ResolvedPackageId`/`IsMissing`, with explicit precedence (**a present real match outranks an alias**) and a `ResolvedVia` marker so grid and loader read the same truth. Treat window counts as **time-relative**: recompute on schedule + on read when `ComputedAt` is stale, or compute on-the-fly from an indexed `UsageEvent`. Make `latest`/substitution recompute **incremental** (touch only edges targeting the changed `(Creator,Package)`, via a per-`(Creator,Package)` "current latest" pointer) and record a resolution-changed **audit event** — never silently mutate a preset's expansion. Distinguish a **pinned** preset resolution from live `latest`.

### R8. The read model must be a materialized table with real indexes  🟠 HIGH (perf-critical)
`PackageListItem` as a **VIEW** with aggregate/computed sort columns (`SUM(size)`, `COUNT`, tier/class joins, `EXISTS` for missing-deps) forces a full aggregation + temp-sort on **every page fetch** when sorting by size/last-used — reproducing the exact "sort is slow" pain the app exists to kill. SQLite has no materialized views and can't index a VIEW/`SUM` column. And **keyset pagination is incompatible with TreeDataGrid's random-access scrollbar** and with non-unique computed sort keys. *(Perf-CRIT1, CRIT2, MED9)*
**Resolution:** make `PackageListItem` a **real materialized table** with denormalized stored aggregates, refreshed per-event by R7's pipeline (strike the "or a VIEW" option). Add **one composite index per supported sort order**, each ending in `Id` (e.g. `(Class, LastUsedAt DESC, Id)`). For scrollbar random access, maintain a lightweight **ordered rowid snapshot per active (filter, sort)** and index into it — giving the grid O(1) `rows[i]` without deep `OFFSET`. Index the **actual dedup keys** `ContentSignature`/`PayloadSignature` (the draft indexed the lazy, mostly-null `ContentHash`); `ANALYZE` after bulk load.

## Remaining findings & resolutions (by area)

### Dedup engine reliability (the CJK-var population it exists to rescue)  🟠 HIGH
- **Signature over decoded strings, not raw bytes** — mojibake entry names decoded as UTF-8 become `U+FFFD`, making the signature non-deterministic on exactly the broken vars we target (*VaM-5*). Also unhandled: **Zip64** (large asset vars), **directory entries** (present/absent across identical vars), and path **normalization** (case/separators/Unicode NFC, set-vs-multiset) (*Corr-M1*). **Resolution:** hash the **raw entry-name bytes**; handle Zip64; exclude directory entries; pin canonicalization (separators→`/`, NFC, explicit case-fold, sorted **multiset**).
- **Encoding-fix changes every entry path → the fix and its original never group as duplicates** (*Corr-M2, VaM-6*). **Resolution:** add a **content-only signature** over the sorted `(uncompressedSize, CRC-32)` multiset **excluding paths** for original↔fixed lineage, plus an explicit `FixLineageId`/`FixedFromVarFileId` link so the broken original can be superseded (not flagged as a rival copy). Store `DetectedCodepage` + `BrokenEntryCount`/confidence (the health report groups by encoding — that data must be persisted).

### Missing VaM-domain entities  🟠 HIGH
- **User's own saves ignored → reclaim/orphan wizard is a data-loss tool** (*VaM-3*). A var no *package* needs but three of the user's scenes need is swept up as an "orphan." **Resolution:** add `UserSave(path, mtime, type)` + `SaveDependency(UserSaveId, DependsOnRef, ResolvedPackageId)` (the old `savedepens`); fold user-save dependents into the reverse closure and orphan/reclaim logic.
- **No AddonPackages profile model; activation can't represent alias links** (*VaM-4, VaM-11, Corr-M5*). `ActivationState` is single-profile, keyed by Package, and can't express a renamed alias link (`A.Missing.1.var` → package `B.Real.3`) or which physical copy is linked. **Resolution:** add a **`Profile`** entity and scope activation to it; key activation by **`VarFileId`** (choose the hottest **online** copy); add `LinkKind (Install/Alias/Temp)`, nullable `AliasedMissingRef`, `LinkSubfolder` (VaM browser grouping), and `LinkType (Symlink/Hardlink)`. Decide the switch mechanism (fast **directory-swap** vs. per-file linking) — per-file linking a 5,000-var preset could be **slower than the old tool** it replaces.
- **"Chosen" vs "pulled-in-only" not modeled** — can't hide dependency-only vars or safely deactivate (*VaM-13*). **Resolution:** add `Reason (Explicit/DependencyOf/Temp)` + preset attribution to activation, so deactivation reference-counts auto-pulled deps.
- **Dependencies only from `meta.json`; `SELF:` unhandled** (*VaM-12*). Scene/`.vap` files embed dependency refs anywhere in the JSON; `SELF:/` must resolve to the container package. **Resolution:** harvest edges from embedded scene/vap content too (tolerant scan); resolve `SELF:` to the container (exclude from missing); **record** refs the grammar can't parse rather than silently dropping them.

### Presets / aliases portability & semantics  🟡 MEDIUM-HIGH
- **Export serializes local surrogate `Id`s** → meaningless on another machine; `latest` resolves differently → "same preset" loads a different set (*Corr-M6, VaM-7*). **Resolution:** serialize presets/aliases purely by **`VarName`/`MissingRef` strings**; record resolution intent (exact vs latest) + a `ResolvedVersion`/`IsVersionSubstituted` snapshot per member with an optional **pin**; re-resolve on import with a **reported diff**.
- **`ResolvedPackageId` FKs dangle on version delete** (*Corr-M4*). **Resolution:** `ON DELETE SET NULL` on all three (`Dependency`/`PresetMember`/`VarAlias`) + mandatory re-resolution in the same transaction; never cascade-delete preset/alias rows (they persist to re-resolve against a future import). Version-pruning reverse-closure must include `PresetMember`, `VarAlias`, `ActivationState`, **and `SaveDependency`** (*Loss-M4*).

### Performance (index-time & runtime)  🟠 HIGH / 🟡 MEDIUM
- **4 TB HDD-resident index is I/O-bound, multi-hour** — the "we're fast now" first impression (*Perf-CRIT3*). **Resolution:** freshness by **`(size, mtime)` from the directory entry alone** (no file open); parallelize **per physical drive** (degree=1 on HDD, high on NVMe — detect media type); make signature + thumbnail extraction a **staged background pass** after name/dep indexing; make it resumable and honest about duration.
- **FTS5 over content paths bloats the index + triggers write-amplify bulk load** (*Perf-HIGH4*). **Resolution:** index a **curated blob** (creator/package/tags/description/type words/gender), **not** raw paths; bulk-load with FTS triggers **disabled**, then `rebuild` once; triggers only for incremental single-var edits; external-content FTS.
- **WAL "never blocks UI" is half-true** — long UI read snapshots pin the WAL (unbounded growth during a multi-hour scan); interactive writes queue behind bulk batches (*Perf-HIGH5*). **Resolution:** short-lived UI read transactions; `wal_autocheckpoint` + periodic `wal_checkpoint(TRUNCATE)` between modest batches; a dedicated write connection/queue giving **interactive writes priority** over bulk.
- **EF Core+SQLite migrations trigger full-table rebuilds** on multi-GB tables at startup (*Perf-HIGH8*). **Resolution:** prefer additive nullable columns; run big migrations in the **background with progress**, not synchronously at launch; keep churny tables (UsageEvent, ContentItem) lean; test migration time against a synthetic 2M-row DB before locking schema.
- **UsageEvent unbounded + global recompute + reverse-closure blowups/cycles** (*Perf-HIGH6, HIGH7*). **Resolution:** compact events older than the largest window into per-package rollups; recompute **incrementally** (only packages with new events) and centrality **only on graph change**; add **cycle detection + depth cap** to closure CTEs and a hot-node closure cache; store `HasMissingDeps` (direct) as a materialized bit. (DuckDB earns its optional place here if analytics grow.)
- **Exact COUNT per keystroke** (*Perf-MED10*) → debounce; approximate counts ("~12K"/"1000+"); cheap `COUNT` off the materialized table. **700K loose thumbnail files** (*Perf-MED12*) → **packed thumbnail store** (blob files / dedicated thumb DB) keyed by PackageId on the fastest tier; decode off-thread with prefetch.

### Reconciliation & environment safety  🟡 MEDIUM
- **Reconcile deletes files/links it didn't create** (*Loss-H5*) → only remove links the app **provably created** (ownership marker); treat "missing on an offline repo" as **unavailable, never removed**.
- **Wrong-drive re-point** rebinds a Repository to a different volume (*Loss-H6*) → require `VolumeSerial` match on re-point (or explicit warned override); mismatch → mount read-only + ask.
- **Registering `{vampath}\AddonPackages` (or a nested/overlapping path) as a repo** (*VaM-14*) → reject at registration; persist the VaM install path as a first-class setting used in the check.
- **Encoding-fix output not validated against VaM's loader** (*Loss-H7, VaM-6*) → validate the rebuilt var against VaM constraints (ZIP+Deflate, UTF-8 flag set, no Zip64/data-descriptors) before preferring it; **never overwrite in place** — keep the original as a first-class retained copy until the fix is proven good. Auto-fix mode **flags/queues, never deletes** originals; surface low-confidence codepage detections for review.
- **Intake auto-classify discards a good download vs. an offline/corrupt library copy** (*Loss-H8*) → apply the R4 predicate to intake; prefer keeping the fresh, verifiable copy.
- **External mirror tools traverse symlinks** (`robocopy /MIR`) and delete through to the real file (*Loss-L1*) → document; prefer safe link types; warn against mirroring AddonPackages.

### Lower / watch  🟢 LOW
- **Timestamps**: store all `UsageEvent.Timestamp` in **UTC**; normalize `VamLogImport` (VaM-local) at import; evaluate windows in UTC (*Corr-M3*).
- **QuickHash freshness false-negatives** (same size+mtime, mid-file change) → include central-directory offset/count or CRC-of-CRCs; periodic deep re-hash of single-copy files (*Corr-L2, Loss-L2*).
- **Hysteresis makes `Class` non-reproducible** after restore/reindex → persist raw `Score` history / last-flip so `Class` is reproducible from stored state (*Corr-L3*).
- **Dependency rows not deduped / self-refs inflate centrality** → `UNIQUE(PackageId, DependsOnRef)` + drop self-edges (*Corr-L4*).
- **Version `int` + `latest = max` mis-picks non-monotonic re-uploads** → tie-break by `MetaDate` or document version-number authority + surface the anomaly (*Corr-L5*).
- **Per-ContentItem favorite/hide** — VaM stores `.fav`/`.hide` **per content item** (`AddonPackagesFilePrefs`); package-level `IsFavorite` can't round-trip it, and the visual gallery browses items (*VaM-8*) → add `ContentItemPref` + an import/reconcile path; keep `Package.IsFavorite` as a convenience aggregate.
- **Preview representative image + placeholder** — asset/morph/plugin vars have no preview; the gallery would show blank tiles (*VaM-9*) → define representative-preview selection + type placeholders + the sibling-JPG pairing rule.
- **`PrimaryType` selection + multi-gender rollup + normalized content counts** (*VaM-10*) → deterministic type precedence (or multi-valued facet); gender confidence + rollup; consider `PackageContentCount(PackageId, Type, Count)` instead of fixed columns (avoids a migration per new content type).
- **Non-compliant `PackageId=null` files invisible in the read model** (*Corr-L1*) → an "unrecognized" projection + auto-suggest identity when their `ContentSignature` matches a known VarFile.
- **Quarantine-dir interop** — existing libraries physically use `___VarRedundant___`/`___StaleVars___`/`___OldVersionVars___`/`___DeletedVars___`; import must recognize these as soft-deleted/stale, not live (*VaM-note*).
- **FAT/exFAT/network mtime** (2s granularity, DST/TZ) can trigger spurious re-index of removable/network repos — note the fragility.

## Decisions that need YOU (product calls, not pure engineering)

1. **Preset-switch mechanism** — fast **directory-swap** profiles (old tool's approach; instant switch) vs. **per-file linking** (flexible but potentially slower than the tool it replaces for a 5,000-var set). Affects the loading-preset feature and the Profile/ActivationState model.
2. **Gallery random-access UX** — keep TreeDataGrid's scrollbar-jump via a materialized ordered snapshot (my recommendation), or accept **filter + "load more"** cursor paging.
3. **Migration/dedup automation** — confirm: **always propose, never auto-delete/move**, single-copy hard-gated? (The reviews strongly favor this given irreplaceable data.)
4. **Non-ASCII case-folding** — accept SQLite `NOCASE` (ASCII-only) or invest in an app-computed Unicode fold key for non-ASCII creator names.
